## 1. 统一目标与验收

### 1.1 North Star（五条，缺一条不算成）

1. 观众戴上帽子，**3 秒内帽子先开口**（无需唤醒词、无需手机、无需配对）；
2. 60–90 秒内完成一次会话，**至少引用 1 个观众刚说过的词**；
3. 宣布学院时**全场听得到**（帽内低语 + 外置音箱同时出声）；
4. 同一顶帽子**连演 10 次不重启**，四院分布不塌（任一学院 ≤40%）；
5. **拔网 1.2 s 内**进入按钮模式并仍能演完。

### 1.2 三层完成定义（Definition of Done）

| 层 | 完成定义（6 条，全绿才算完） |
|---|---|
| **硬件** | ① 帽本体 ≤150 g、整机 ≤350 g、ΔW ≤120 g；② 平衡点落帽箍中心 ±3 cm；③ 1 m 68–72 dBA；④ 帽体隔离度 ≥25 dB；⑤ 连续 2 h 温升 <10 ℃；⑥ 20 秒换人流程连过 10 次 |
| **下位机** | ① 冷启动到可听 ≤3 s；② 10 次会话不重启；③ 心跳 15 s、断网 5 s 内进 OFFLINE；④ 按钮打断 300 ms 内静音；⑤ 六态灯语正确；⑥ 低压保护触发后能播完当前句 |
| **上位机** | ① 三个 adapter 可单跑；② 判决纯函数单测通过（含反集中）；③ 四类超时都能降级；④ 6 时间戳齐全、误差 <200 ms；⑤ 预热一条命令跑完；⑥ 大屏 console 显示字幕与延迟 |

### 1.3 延迟的三层口径（不要再混用）

| 口径 | 值 | 用在哪 | 谁认 |
|---|---|---|---|
| **预算合计** | 1.24 s | 方案与 PPT（分段相加） | 全员 |
| **上台验收** | 1.8 s（中位，10 次） | 彩排 Gate G8 | 主讲 |
| **内部 Gate** | 2.5 s（不过即砍环节） | 11/16 23:30 | 全员 |

**三问（记在墙上）**：硬件→固件 = 引脚表 + 机械事实 + 可听录音；固件→上位机 = **可重放的抓包**（所以能离线开发）；上位机→演示 = 预热端点 + 延迟证据 + 四院分布。

### 2.3 一条数据走完全程（trace 例子，用来验收"真的接上了"）

```
按下/戴上  →  fw 记 t_arm（单调 ms）→ 灯白呼吸（ARMED）
第 1 帧音频 →  ws_tx 发 type=0x01 seq=0 …（60 ms/帧）
末字        →  fw 记 t0，发 {"type":"vad","ev":"speech_end"}
            →  fw 立刻播预录沉吟（TTFV ≈0.4 s）
网关        →  收末帧记 t1 → ASR final 记 t2 → 下发 {"type":"stt","text":…}
LLM        →  首 token 记 t3 → 代码 argmax + 反集中 → 台词
TTS        →  首包记 t4 → 下行 Opus 帧
帽子        →  沉吟首帧记 t5a、真实内容首帧记 t5b → 灯转学院色
会话末      →  下发 {"type":"result","house":"courage","reasons":[…],"latency":{…}}
落库        →  host 写一行 JSONL：t_arm/t0/t1/t2/t3/t4/t5a/t5b + house + fixture 编号
```

**验收方式**：拿这一行 JSONL 与秒表对账，`t5b−t0` 与秒表差 >200 ms 即判本次指标不可信，重测。

## 3. 通信准则（规定"怎么改"，不重抄协议）

### 3.1 治理

| 项 | 规定 |
|---|---|
| owner | **B 唯一编辑权**（协议落在服务端），改动需 **A 复签**（设备实现方），C 只读 |
| 事实源 | `docs/00-protocol.md`；`docs/proto/*.schema.json` 由它生成，**不得手改**（CI 比对生成结果） |
| 变更三处同步 | 协议文档 / `fw/net/proto.c` / `host/app/proto/schema.py` 的**消息名、字段名、错误码集合必须相等**，CI 校验 |
| 定案 | 线协议用 **snake_case**（对齐 xiaozhi 上游 `audio_params`/`sample_rate`）；`stt`（不用 `asr`）、`abort`（不用 `interrupt`）——两者都是 xiaozhi 的既有字段，路线①不用改固件 |

### 3.2 时间戳（3 + 4，缺一条本次指标作废）

| 侧 | 必记 | 用途 |
|---|---|---|
| 设备（**单调时钟 ms**，上电起） | `t_arm` 触发戴上、`t0` 末字、`t5a` 沉吟首帧、`t5b` 真实内容首帧 | **TTFV = t5a−t0**（含沉吟）；**TTFC = t5b−t0**（对外只报这个） |
| 服务端 | `t1` 末帧到达、`t2` ASR final、`t3` LLM 首 token、`t4` TTS 首包 + `recv_wall`（UTC） | 分段归因 |
| 铁律 | 设备**只产生单调时钟**；UTC 由服务端补写；设备不做 NTP | 漂移会把 TTFC 算成负数 |
| 两个阈值 | 对账误差 **>200 ms ⇒ 本次指标作废**；**>500 ms ⇒ 记 `103 clock_skew`** | 前者是验收，后者是错误码，别混 |

### 3.3 错误码（以 7 个旧码为基线，只加不改）

| 码 | 语义 | 归属 | 降级/动作 |
|---|---|---|---|
| `auth_failed` | 鉴权失败 | 3xx | 人介入换 token |
| `session_expired` | 会话过期 | 3xx | 新会话 |
| `rate_limited` | 限流 | 3xx | 退避 + 提示 |
| `bad_frame` | 帧非法 | 1xx | 丢弃并计数，不断连 |
| `asr_timeout` | ASR 超时 | 2xx | 「我没听清，再说一次？」 |
| `llm_timeout` | LLM 超时 | 2xx | 模板首句 + 兜底打分 |
| `tts_timeout` | TTS 超时 | 2xx | Polly / 预录音 |
| **新增** | `clock_skew`(1xx) / `upstream_5xx`(2xx) / `protocol_unsupported`(3xx) | — | 新码须在协议码表、`fw/net/errors.h`、`host/app/errors.py` **三处同时登记** |

规则：`error.fatal` **只在 3xx 出现**；1xx/2xx **必须**带 `degrade` 字段说明用了哪个兜底——评委问"断了怎么办"，就查这个字段的统计。

### 3.4 版本协商与兼容

| 位 | 谁提 | 规则 |
|---|---|---|
| 子协议 | 设备 `sortinghat.voice.v1` | 主版本不匹配**拒握手**；次版本不拒 |
| `caps` | 设备在 `hello` 报能力 | 服务端**只下推设备声明支持的**（`vad:"device"` 就不发服务端 VAD） |
| `budget_ms` | 服务端在 `ready` 报预算 | 设备据此定预缓冲帧数 |
| 版本 | `vMAJOR.MINOR.PATCH` | MAJOR=接口破坏；MINOR=加可选字段/消息；PATCH=实现修复 |

**四条兼容底线**：① 只增不改不删（新增必 optional 且写缺省语义）；② **未知即忽略**——收到未知 `t`/字段静默丢弃并计数，**不许回 error**（要有单测）；③ 语义变更=改名（"3 条理由"改"≤3 条"也叫 `reasons_v2`）；④ 服务端兼容 N 与 N−1（本期只需 v1）。

### 3.5 Fixture 与回放（固件交付物的真正形态）

| 要求 | 做法 |
|---|---|
| 采集 | 文本帧全记；二进制帧**只记头**（type/seq/len），音频留首尾各 3 s；写 `fixtures/session-<dev>-<yyyymmdd-HHMM>.ndjson` |
| 脱敏 | 音频不落盘；`stt.text` 存哈希+长度，明文进 `fixtures/private/`（.gitignore） |
| 回放 | `host.replay <fixture>` 走**同一份 code path**，上游响应打 `providers/cassettes/`；须复现状态序列、`result.house`、6 时间戳（相对误差 <50 ms） |
| 门禁 | CI 跑三条：happy / `asr_timeout` / 断网；任一条 `house` 变了即红 |

### 3.6 逐消息责任表

| 消息 | 生产方 | 消费方 | 失败处理 |
|---|---|---|---|
| `hello` / `ready` | 设备 / 云 | 云 / 设备 | 3 s 无 `ready` → 退避重连 1/2/4/8/15 s |
| `listen{start/stop/detect}` | 设备 | 云 | 5 s 无响应 → 回 ARMED，灯闪一次 |
| `vad{speech_start/end}` | 双向 | 双向 | 不一致取"更早 start + 更晚 end" |
| 二进制 Opus 帧 | 双向 | 双向 | 不重传；跳号 >10 记 `bad_frame` |
| `stt{partial/final}` | 云 | 设备（可选） | 超时 → 提示句 |
| `llm{delta}` | 云 | 设备（可选） | 超时 → 模板首句 |
| `tts{start/sentence_start/stop}` + 音频 | 云 | 设备 | 首包超时 → 预录音 |
| `result{house,reasons,latency}` | 云 | 设备 | 缺失 → 只播 TTS |
| `abort` | 设备 | 云 | 忽略失败，本地静音优先 |
| `ping` / `pong` | 双向 | 双向 | 30 s 无 `pong` → 重连 |
| `bye{reason}` | 设备/云 | 双向 | `done` / `doff` / `silence` / `timeout` |

## 4. 仓库施工准则

> 一条总则：**新人 30 分钟内能独立跑一次验收。**

| 项 | 规定 | 检查 |
|---|---|---|
| 目录 | 七个顶层，不许新增：`hw/ fw/ host/ docs/ fixtures/ release/ tools/` | `tools/check_tree.py` |
| 分支 | `main` 保护；`feat/<area>-<slug>`、`fix/`、`exp/`（可删）；**分支寿命 ≤6 h** | 合并即删 |
| 提交 | `<area>: <动词><对象>` ≤50 字符；body 写"为什么"；**必带 `Refs: G1` 或 `Refs: RFC-003`**；破坏性改动标题加 `[BREAKING]` | commit-msg 正则 |
| PR | 四段：改了什么 / 影响哪层 / 验收命令与输出 / 回滚方法 | 模板 |
| CODEOWNERS | `hw/` `fw/` → A；`host/` → B；`host/persona/` `release/` `docs/ppt/` → C；`docs/00-protocol.md` → **A+B 双签** | 谁必须看 |
| **CI 七关** | ① fw 编译 ② host 单测 + lint ③ 协议 lint（三处集合相等）④ 体积（bin ≤4 MB、model ≤6 MB、预录 ≤300 KB）⑤ 文档死链 + 单一事实源 ⑥ **数字比对**（对外材料里的数字必须能在 `hw/measurements/` 找到同名文件）⑦ **fixture 三条回放** | 每关一个 `make`，本地与 CI 同命令 |
| 密钥 | 只进 `.env.local` 与 CI secrets；**设备 token 不进固件源码**，走 NVS 首次配网写入 | `gitleaks` pre-commit |
| 大文件 | >1 MB 不进 git（STL/视频/bin 走 `release/` + 对象存储），git 只放 `SHA256SUMS` 与链接 | `.gitattributes` |
| 发布物 | `sortinghat-<kind>-<yyyymmdd>-<git7>.<ext>`：`-fw-` `-video-` `-img-` `-deck-` | `make release` 自动带 git7 |
| 上游锁定 | `fw/UPSTREAM.md` 记录 xiaozhi / TuyaOpen 的 **commit + tag**；**赛期不 `git pull`** | 提交前检查 |

## 7. 对用户清单与流程图的裁决

### 7.1 重量与成本：<120 g 与 ¥100 到底怎么定义

| 口径 | 定义 | 目标 | 现状 |
|---|---|---|---|
| **帽本体** | 买来的帽子，不装任何东西 | **≤150 g**（当场称，>170 g 不买） | 市售 150–300 g |
| **改造增重 ΔW** | 整机 − 帽本体原重，同一台 0.1 g 秤测两次（比"载荷包"更好证伪） | **≤120 g** | 1000 mAh + EVA 后腔 + 剪排针后 90–150 g |
| **整机** | 帽 + 全部电子与结构 | **≤350 g**（硬上限 300 g 更稳） | 240–450 g |

- **"总重 <120 g" 只能指 ΔW**：帽本体单体就 150 g+，整机 120 g 物理不成立。
- **"成本约 ¥100" 只能指单顶电子件**（不含帽、外置音箱、备件）：实测 **¥100–200**（S3 N16R8 ¥35–50、INMP441 ¥8、MAX98357A ¥5、喇叭 ¥8、1000 mAh ¥12、TP4056 ¥3、灯/开关/线 ¥15–30）。**整顶 ¥200–400**；两顶 + 音箱 + 耗材 + 云 **¥600–1345**（主报告 §13）。
- **BOM 改单 owner：A，今天 18:00 前**（1000 mAh 替换、剪排针、EVA 后腔都要落到 `hw/bom.csv`）。

### 7.2 供电：1000 mAh 撑不撑得住

| 口径 | 功率 | 800 mAh 可用（2.96 Wh） | 结论 |
|---|---|---|---|
| 连续会话 | 0.75–1.1 W | **2.7–3.9 h** | "3–4 小时"成立，但只在这个最坏口径 |
| 展台混合（90 s 演 + 120 s 换人） | ≈0.026 Wh/人 | ≈110 人 / ≈8 h | 一天够 |
| **宣布瞬间峰值** | 喇叭 320 mA + S3 350 mA + 灯 100 mA ≈ **0.7–0.8 A** | — | **真瓶颈** |

**采购硬指标**：电芯持续放电 **≥1.5 A**、保护板 **≥2 A**；否则宣布那一刻掉压重启。买不到就并两颗或退回 2000 mAh（+18 g，破 ΔW）。**展台仍备 2 块**——换电理由是无充电窗口（满充 4–4.5 h）与单点故障，不是容量。

### 7.3 麦克风：位置与朝向是两件事

**结论**：不用"贴帽檐最前缘"（帽檐下垂变形会让麦位与增益随人变）；落点 **帽箍前带、额前 2–3 cm、声孔朝下后 30–45° 指向嘴**，离鼻息轴线 ≥15 mm。

| 判据 | 阈值 |
|---|---|
| 嘴到麦 | **≤14 cm** |
| 麦孔—喇叭中心 | **≥25 cm** + 毛毡 + EVA 隔断 |
| 气噪 | "怕/破/扑/噗/夫/呼"6 音无削顶 |
| 可懂度 | 20 句普通话 ASR 字错率 ≤10%（开孔/不开孔对比） |

> INMP441 是全向麦，"朝嘴"不是指向性收益，而是**缩短距离 + 避开鼻息**；防风棉必须有。

### 7.4 喇叭：否决"正顶下投"，用后壁 + 短号角

| 方案 | 到耳 | 到麦 | 重心 | 判定 |
|---|---|---|---|---|
| 帽冠正顶下投 | 12–15 cm | 20–25 cm ⚠ | 最高点，破"顶部不放重物" | ❌ |
| **帽冠后壁下缘 + 20–30 mm 短号角引到后上部、朝前下 15–20°** | 8–12 cm（近场 +6~10 dB） | ≥25 cm ✔ | 力臂 ≤6.5 cm，与电池对置配平 | ✅ |
| 帽檐内侧 | 6–10 cm | 10–12 cm ❌ | 低 | ❌ 破隔离 |

**关键物理**：帽内仅 40–60 cm³ 腔，`fc` 压不到 250 Hz（需 150 cm³）——"从头顶往下传"补不了低频，真正起作用的是**离耳 8–12 cm 的近场增益**。
验收：① 1 m 68–72 dBA ② 耳侧 78–80 dBA ③ 半双工下播放时麦处泄漏 ≤−30 dBFS ④ 3 人盲听 ≥2/3 答"声音在耳边"。

### 7.5 佩戴触发：唯一入口，但要选对传感器

**结论**：**FPC 微动（主）+ 反射式近距（辅）取"或"**，按钮只做打断/静音；**电容否决**（一次性内衬 + 头发使基线漂移）；**PIR 否决**（测运动，戴上不动就掉）；**唤醒词不做**（70–80 dBA 下误/漏唤醒，定制 2–3 周）。

| 维度 | 微动（主） | 反射近距（辅） | 按钮 |
|---|---|---|---|
| 20 秒轮换 | ✅ 摘下即结束 | ✅ 非接触 | ⚠ 要教"先按一下" |
| 误触发 | 低（机械行程） | 中（深色头发/暗光需实测） | 近零 |
| 失效模式 | 顶不到 | 不触发 | 按不到 |

状态机（**六态，G1 冻结，不许再加**）：

| 态 | 触发 | 灯 | 麦 | 上行 |
|---|---|---|---|---|
| **OFF** | 摘下 / 上电 | 灭 | 静音 | 无 |
| **ARMED** | 戴上（200 ms 消抖） | 白呼吸 | 只听 VAD | 无 |
| **LISTENING** | 首句起振 / 按钮 | 青常亮 | 开 | Opus 帧 |
| **THINKING** | `vad{speech_end}` | 琥珀呼吸 | 半双工静音 | 无（等 `stt`） |
| **SPEAKING** | `tts{start}` | 学院色 | 静音 | 无 |
| **ERROR** | 不可恢复错误 | 红闪 2 次 | 静音 | 错误上报 |

`OFFLINE` 不新增态：复用 **ARMED 的黄常亮**（按钮模式），这样灯语仍是 6 种。

状态机：`IDLE` 拆 **OFF**（摘下：麦静音、灯灭、不上行）与 **ARMED**（戴上：灯白呼吸、等首句 ≤5 s）；**戴上 200 ms 消抖 + 5 s 冷却**；**摘下 2 s 内发 `abort` + `bye{reason:"doff"}`**，不给下一位留残局；误触发预算 ≤1 次/10 人，超了退回按钮。

### 7.6 TuyaOpen：能做，但不该做主链路

| 项 | 判断 |
|---|---|
| 事实 | 支持 T2/T3/T5AI/**ESP32/ESP32-C3/ESP32-S3**；1,948 star；2026-11-13 仍在提交；**许可证字段为 `Other/NOASSERTION`（Apache-2.0 说法需核实）** |
| 角色音色 | 音色由**云侧 TTS** 决定，无公开 instruction/风格接口（需核实）；"七十岁、沙哑、慢"大概率做不到 |
| 用户给的理由 | **不成立**：说"离线 TTS 太机械"，但离线 TTS 只做断网兜底、本就不在主链路；TuyaOpen 给的是另一套**云端** TTS，不是更好的 TTS |
| 代价 | 换固件栈 4 h 高风险、与 G3 撞车；**涂鸦云不可观测 ⇒ 6 时间戳拿不全，TTFC 讲不出来** |
| 裁决 | 主链路 CosyVoice instruction；TuyaOpen 仅在赛方发已烧 license 的 T5AI-Core 时做"第三顶帽子"拿生态分 |

### 7.7 Nemotron 与 Kiro：两处必须纠正的说法

| 说法 | 判定 | 正确表述 |
|---|---|---|
| "Nemotron 是运行时超级大脑" | 半对：它是 LLM，可做第二判官，但**不在帽子里跑**（帽内 8 MB PSRAM，与最小 Nemotron 差 3 个数量级） | 云上的第二判官 |
| "Nemotron 是本地语音引擎" | ❌ 错。NVIDIA 的语音栈是 **Riva**，ASR 是 **Parakeet** | Nemotron ≠ 语音引擎 |
| "Nemotron 跑在 Bedrock 上" | Bedrock 模型卡确有 Nemotron（9B v2 标 Legacy / Nano 3 30B / Super 120B）；NIM 目录有 `nemotron-super-49b-v1`、`nemotron-ultra-253b-v1`；**中文稳定性需实测** | 说"经 Bedrock 或 NVIDIA NIM 调用" |
| "Kiro 是 AI 编程工程师" | 基本对；精确说：**规格驱动的编码助手/IDE/CLI**，产出 spec + diff | 开发期把 spec 变成代码与测试 |

**给评委的一句话（照念）**：
> "开发期我们用 Kiro 把 spec 变成服务端代码与测试；运行时 Nemotron 在云上做第二判官，和主模型做一致性对照；帽子里只有一颗 ESP32-S3——它负责听、传、放，不负责思考。"

### 7.8 对"TuyaOpen + 涂鸦 ASR + NIM + 涂鸦 TTS"新流程图的裁决

**判定：骨架同构、中段黑盒，只能做备链/生态分演示，不能做主链路。**

| 段 | 新图 | 判定 |
|---|---|---|
| 帽内 S3 + INMP441 + MAX98357 | 保留 | ✅ 可采用 |
| 戴上触发开关 | 保留 | ✅ 可采用（选型见 §7.5） |
| 固件栈 TuyaOpen | 异构 | ⚠️ 换栈 4 h，与 G3 撞车 |
| 涂鸦云 ASR / 轻量中转 | 异构 | ⚠️ 可作第三 provider |
| 云端 NIM（Nemotron Super）主判官 | 异构 | ❌ 主判官不可换（延迟 + 中文未验证） |
| 涂鸦 TTS + "分院帽复刻音色" | 异构 | ❌ **权利风险**（见下） |
| 头顶喇叭 | 异构 | ❌ 同时破"≥25 cm"与"顶部不放重物" |

**缺的四层**：① **判决层**（图里让大模型直接给学院；必须 `house=argmax(scores)` 由代码算）；② **反集中层**（连续 3 次同院 ×0.85、第 4 人强制换院）；③ **降级层**（涂鸦云一断即零兜底）；④ **观测层**（涂鸦云不给 t1–t4，TTFC 讲不出来）。
**延迟与成本**：链路多两跳跨境；本项目实测冷 TLS 0.78–1.76 s，多两个冷连接就是 +1.5–3.5 s；NIM 大模型首 token + 涂鸦 TTS 首包（无公开数字）估 2.6–4.5 s，**直接打穿 1.8 s 上台线**；成本从 ¥0.145/次变成"涂鸦云未公开价 + GPU 时租"，**不可预算比贵更致命**。
**音色"复刻"的权利风险（本图最硬的一处）**：① 电影分院帽的中文配音是配音演员的表演，《民法典》第 1023 条对自然人声音的保护参照肖像权——未经书面同意"复刻"即侵权；② 角色名 + 音色叠加 = 华纳 IP 与声音权双雷，"标注致敬"不是抗辩；③ 《AI 生成合成内容标识办法》2025-09-01 起要求显式标识；④ 涂鸦云是否允许自带复刻音色取决于平台条款（需核实）。
**裁决：不做复刻**，做 instruction 描述的原创老年男声，并把"我们评估过复刻的法律风险，所以做原创音色"写进 pitch——这本来就是设计好的加分页。

**AWS 加分**：新图里一个 AWS 组件都没有 → 按图打分直接归零。要让加分成立，**主链路必须留 AWS**（Transcribe / Bedrock / Polly 兜底 / CloudWatch 至少三件）。

### 8.3 断电 / 重启恢复（现场换电必踩，两份盲评都漏了）

**问题**：换电池、低压保护、看门狗重启都发生在"已经宣布到一半"的时候——重启后如果重播宣判，观众会听到两遍；如果不播，又像死了。

**做法：NVS 会话账本 + 一次幂等判断**

| 字段 | 写入时机 | 用途 |
|---|---|---|
| `sid` / `boot_id` | 会话开始 / 每次上电 | 判断"是不是同一次会话" |
| `state` | 每次状态切换 | 重启后知道停在哪 |
| `house` / `announced` | 收到 `result` / 播完宣布 | **`announced=true` 则重启后只亮灯、不再播** |
| `last_msg_id` | 每次 `result` | 幂等：同一 `result` 只播一次 |
| `fixture_seq` | 每次会话 | fixture 文件名续号，不覆盖 |
| `err_count` | 每次错误 | 连续 3 次 ERROR → 禁自动重启，等人工 |

**换电 SOP（贴在内衬里）**：长按 2 s（保存账本并静音）→ 关机 → 换电 → 开机 → 若仍戴着则直接回 ARMED；若已摘下则回 OFF。
**验收**：在 SPEAKING 中途拔电，重启后 **不得重复宣布**；在 THINKING 拔电，重启后回 ARMED 并允许重说一次。两条都进彩排 3（G8）。
