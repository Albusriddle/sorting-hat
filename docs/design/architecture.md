# 分院帽 · 工程架构：上位机 / 下位机 / 硬件分工

> 目的：把「一顶会说话的帽子」拆成三块可并行开发、可独立验收的工程边界，并写清它们之间的契约。
> 依据：`SORTINGHAT-可行性与实施方案.md` + `sortinghat/analysis/01~05`。
> 时间基准：2026-11-15，提交 11/18，路演 11/21。
> 一句话：**下位机负责"听得见、说得快、不崩"；上位机负责"听得懂、判得对、讲得像"；硬件负责"装得下、戴得住、传得清"。**

│                         ▼                    ▼
│                    ┌──────────────────────────────┐
│  WS2812 灯环 ◀──── │   ESP32-S3（16MB Flash/8MB PSRAM）│ ────▶ 偏心马达(选)

│  电池 ADC ◀──────── │                              │
│                    └──────────────┬───────────────┘

│  内胆筐 / EVA 隔断 / 一次性内衬      │
└────────────────────────────────────┼────────────────────────────────┘
                                     │ WSS（Opus 60ms + JSON 控制）
                                     ▼
┌──────────────────────── 上位机（服务端） ────────────────────────────┐
│  会话网关 ws_gateway ──┬── 编排 orchestrator（状态机/超时/降级）        │
│                        ├── ASR adapter  → Transcribe Streaming(zh-CN) │
│                        ├── LLM adapter  → Bedrock（结构化 JSON）       │
│                        ├── TTS adapter  → CosyVoice-v3.5-flash         │
│                        └── 观测 metrics（6 个时间戳/会话）              │
│  存储 storage（DynamoDB/S3，可选）   监控台 console（大屏字幕/延迟）      │
└──────────────────────────────────────────────────────────────────────┘
```

**一次会话的数据流（90 秒）**

```
戴帽/按钮 → 下位机 LISTENING → Opus 上行×N → 网关 → ASR 流
   → VAD 尾点 → （下位机先播 400ms 预录沉吟）→ ASR final → LLM(JSON)
   → 代码算 house + 反集中 → TTS 流 → Opus 下行 → 下位机播放
   → result{house,reasons,latency} → 灯变色 + 宣布 → 摘帽
```

## 1. 三层职责边界（先把"谁不做什么"写死）

| 能力 | 硬件 | 下位机（ESP32-S3） | 上位机（服务端） |
|---|---|---|---|
| 拾音 | 麦克风、开孔、密封、隔振 | I2S 采集、AFE/NS/VAD、Opus 编码 | 解码（可选）、ASR |
| 放音 | 喇叭、后腔、功放、隔声 | Opus 解码、I2S 播放、抖动缓冲 | TTS 合成 |
| 语音理解 | — | ❌ 不做（本地只有命令词） | ✅ ASR + 语义 |
| 人格判断 | — | ❌ 不做 | ✅ LLM 出证据 + 代码判决 |
| 角色音色 | — | 只存 3 条预录沉吟 | ✅ TTS instruction 音色 |
| 状态与交互 | 灯、按钮、马达 | ✅ 状态机 + 灯语 | 下发 `tts/result` 触发 |
| 断网降级 | — | ✅ 检测 + 切按钮模式 + esp-tts | 不参与（已断） |
| 重连/保活 | — | ✅ 心跳、退避重连、预连接 | 会话续期、限流 |
| 数据留存 | — | ❌ 不落盘 | ✅ 最小化留存（音频不落盘） |
| 观测 | — | 上报设备侧时间戳 | ✅ 聚合 6 段延迟指标 |

**三条不可越界的规矩**
1. **下位机不解析语义、不做判断**——它只会"转发音频 + 播音频 + 点灯"。
2. **上位机不碰音频硬件**——它只处理流和文本；音量、增益、AEC 全在端侧。
3. **硬件不为软件让路**——开孔位置、后腔、重心是物理约束，软件适配硬件，不是反过来。

## 2. 硬件分工

### 2.1 子系统与责任人

| # | 子系统 | 关键件 | 硬指标 | 验收 |
|---|---|---|---|---|
| H1 | 声学拾音 | INMP441（I2S 数字麦） | 帽檐前缘内侧，孔 >1 mm，孔深:孔径 <2:1，硅胶套过盈密封；到嘴 10–14 cm | 录音回放清晰，无风噪 |
| H2 | 声学放音 | MAX98357A + 36 mm 4Ω 3W | **帽冠后壁下缘**（力臂 ≤6.5 cm）+ 20–30 mm 短号角把出声口引到后上部、**朝前下 15–20°**；独立密封后腔；到麦 ≥25 cm | 1 m 处 68–72 dBA |
| H3 | 主控 | ESP32-S3（16 MB Flash + 8 MB PSRAM） | 双核 240 MHz；天线净空区不被毛毡/电池遮挡 | 满负载不死机 |
| H4 | 电源 | 2000 mAh 1S LiPo + TP4056 + 5V 升压 | 电池在**帽箍环带后侧**（力臂 ≤5 cm）；与皮肤间 2 mm 隔热 | 连续 2 h 温升 <10 ℃ |
| H5 | 交互 | 按钮 ×1、WS2812 ×8、偏心马达（选） | 灯限亮度 30%；按钮位置可盲按 | 戴手套也能按 |
| H6 | 结构 | 毛毡帽 + PLA 内胆筐（15% 填充）+ 记忆棉 + EVA 隔断 | 帽本体 **≤150 g**；整机 ≤350 g；Σm·d ≤600 g·cm | 木棒平衡点 ±3 cm |
| H7 | 卫生 | 一次性内衬帽、发网、酒精湿巾 | 20 秒完成轮换 | 连换 10 人不出错 |

### 2.2 板级接口（引脚表示例，按实际板子改）

| 信号 | ESP32-S3 引脚 | 对端 | 备注 |
|---|---|---|---|
| I2S0_BCLK / WS / DIN | GPIO4 / 5 / 6 | INMP441 | 16 kHz、16 bit、单声道 |
| I2S1_BCLK / WS / DOUT | GPIO15 / 16 / 7 | MAX98357A | 24 kHz 输出（或 16 kHz 直出） |
| LED_DIN | GPIO48 | WS2812 灯环 | 8 灯串联 |
| BTN | GPIO0 | 按钮（下拉） | 短按=开始/打断，长按 2 s=静音 |
| VBAT_ADC | GPIO1 | 1/2 分压 | 电量与低压保护 |
| MOTOR | GPIO2 | MOSFET → 马达 | 可选 |
| PWR_EN | GPIO3 | 升压使能 | 深度睡眠用 |
| USB | USB-C | 5V + D+/D− | 烧录 + 充电 |

### 2.3 结构与声学的五条硬约束（软件不可覆盖）

1. 麦孔与喇叭孔之间 **≥25 cm**，中间隔毛毡 + 一道 EVA；
2. 喇叭必须有**独立密封后腔**（无后腔 = 声短路，低频全丢）；
3. 电池不得放帽檐后侧（12–14 cm 力臂 → 帽子后仰）；放帽箍环带层；
4. 帽冠顶部空腔**不放重物**（抬高重心，转头力矩大）；
5. 与头皮接触的一圈只用软 EVA/泡棉，硬 PLA 在环带外侧，留 5 mm。

### 2.4 硬件交付物

- 引脚表 + 接线图（一页纸，贴在工作台上）
- 内胆筐 STL + 开孔模板（打印 2 套，一套备用）
- 称重与配平记录（帽子重量、整机重量、Σm·d）
- 1 m 声压实测（手机声级计 + 校准说明）
- 帽体隔离度实测（官方漏音法：≥25 dB 合格）

## 3. 下位机分工（ESP32-S3）

### 3.1 任务划分（FreeRTOS）

| 任务 | 核 | 优先级 | 周期/触发 | 栈 | 职责 |
|---|---|---|---|---|---|
| `audio_in` | 1 | 5 | 32 ms 帧 | 4 KB | I2S DMA 取帧 → AFE（NS/VAD）→ 环形缓冲 |
| `afe`（可并入 audio_in） | 1 | 5 | 32 ms | 8 KB | ESP-SR AFE：降噪 + VAD；AEC 只在实验开关打开时启 |
| `opus_enc` | 1 | 4 | 有帧即编 | 4 KB | 16 kHz → Opus 60 ms |
| `ws_tx` | 0 | 3 | 有帧即发 | 4 KB | 组帧 + 发送 + 发送队列 |
| `ws_rx` | 0 | 3 | 事件 | 4 KB | 文本 JSON 分发 / 二进制 Opus 入解码队列 |
| `opus_dec` + `audio_out` | 1 | 4 | 60 ms | 6 KB | 解码 → I2S DMA 双缓冲 → 播放 |
| `ui` | 0 | 2 | 20 ms | 3 KB | 灯语状态机、按钮消抖、马达 |
| `power` | 0 | 1 | 1 s | 2 KB | 电池 ADC、低压保护、温升 |
| `supervisor` | 0 | 6 | 1 s | 2 KB | 任务看护 + 喂狗；异常重启并记 NVS |

**看门狗**：硬件 WDT 10 s + 任务看护（audio_in 3 s 无心跳即重启）。

### 3.2 模块划分

```
fw/
├── main/                 启动、配置、任务创建
├── audio/
│   ├── i2s_in.c          麦克风采集（DMA、增益、直流去除）
│   ├── i2s_out.c         喇叭播放（DMA、抖动缓冲）
│   ├── afe.c             ESP-SR：NS/VAD（AEC 可选）
│   ├── opus_codec.c      Opus 编解码封装
│   └── preroll.c         3 条预录沉吟（Flash 内 Opus）
├── net/
│   ├── wifi_mgr.c        配网凭据（NVS）、重连、RSSI
│   ├── ws_client.c       WSS、心跳 15 s、退避重连、预连接
│   └── proto.c           hello/listen/abort/tts/stt 帧编解码
├── ui/
│   ├── led.c             灯语（IDLE/LISTEN/THINK/SPEAK/ERR）
│   └── button.c          短按/长按
├── offline/

│   └── quiz.c            按钮模式 4 题

### 3.3 状态机（下位机只认 5 个状态）

```
        ┌────────┐  戴上/按钮/唤醒词   ┌──────────┐
        │  IDLE  │───────────────────▶│LISTENING │
        └────────┘                    └────┬─────┘
             ▲                             │ speech_end / 按钮
             │ 播放完/超时                  ▼
        ┌────┴─────┐   首帧 TTS       ┌──────────┐
        │ SPEAKING │◀─────────────────│ THINKING │
        └────┬─────┘   （先播沉吟）    └────┬─────┘
             │ 按钮打断                     │ WS 断 / 超时
             ▼                              ▼
        ┌─────────┐                   ┌──────────┐
        │  ERROR  │◀──────────────────│ OFFLINE  │（按钮模式 + esp-tts）
        └─────────┘                   └──────────┘
```

**灯语**：白呼吸=IDLE，青常亮=LISTENING，琥珀呼吸=THINKING，学院色=SPEAKING，红闪 2 次=ERROR，黄慢闪=OFFLINE。

### 3.4 资源预算

| 资源 | 预算 | 说明 |
|---|---|---|
| PSRAM | 740–820 KB（AFE 单麦）+ 100–200 KB（Opus 缓冲）+ 64 KB（解码环） | 8 MB 够 |
| 内部 SRAM | DMA 8 KB + 任务栈 ~35 KB + 协议缓冲 8 KB | 512 KB 够 |
| Flash | app 4 MB + model 分区 6 MB（若开唤醒词）+ 资源 1 MB + NVS 64 KB | 16 MB 够 |
| CPU | AFE 10–15% + Opus 5–10% + Wi-Fi 10% ≈ **单核 30–40%** | 留余量给重连与日志 |
| 启动到可听 | ≤3 s（Wi-Fi 已存凭据 + WSS 预连接） | 现场冷启动要测 |

### 3.5 两条固件路线（与主报告 §5.4 对齐）

| 路线 | 改动 | 工时 | 何时用 |
|---|---|---|---|
| ① 官方固件 + 开源 `xiaozhi-esp32-server` | 改服务器地址、关唤醒词、改灯色 | 1–2 h | **今晚出声** |
| ② 官方固件 + 自建服务端 | 只改协议字段与提示音 | 14–22 h | 需要完全可控 |
| ③ 自研最小固件 | 全部重写 | 41–67 h | 不推荐（3 天内） |

**决策点**：11/17 12:00 前若 ② 没跑通，锁 ① 演完，不再改固件。

## 4. 上位机分工（服务端）

> 本项目的"上位机"= 服务端进程（演示时跑笔记本，路演可迁 EC2/Fargate），**不是** PC 端控制软件。另有一个可选的"监控台"网页，给大屏用。

### 4.1 进程与服务

| 服务 | 职责 | 关键实现 | 降级 |
|---|---|---|---|
| `ws_gateway` | WSS 接入、鉴权、会话管理、背压 | FastAPI/uvicorn 或 Node `ws` | 拒绝新会话，保旧会话 |
| `orchestrator` | 会话状态机、超时、重试、降级决策 | 异步任务 + 每会话 context | 模板句 |
| `asr_adapter` | 流式 ASR | Transcribe Streaming（zh-CN） | 阿里 fun-asr |
| `llm_adapter` | 人格推理 + 结构化 JSON | Bedrock Converse/InvokeModelWithResponseStream | Nova Lite / 模板 |
| `tts_adapter` | 角色音色流式合成 | CosyVoice WebSocket（instruction 音色） | Polly Neural Zhiyu / 预录音 |
| `judge` | 代码判决：`house=argmax` + 反集中 + 理由校验 | 纯函数，可单测 | 固定四院轮转 |
| `storage` | 结果与延迟落库 | DynamoDB/S3（可选） | 本地 JSONL |
| `console` | 大屏：字幕、三条理由、延迟条 | 静态页 + SSE/WS | 纯文本 |

### 4.2 编排时序（含超时预算）

| 阶段 | 预算 | 超时动作 |
|---|---|---|
| 等 `speech_end` | 设备侧 300 ms | **6.5 s 无声 → 帽子主动救场；15 s 仍无 → `bye{silence}`**（不是 12 s 判死） |
| 下发沉吟 | **立即**（缓存音频，0 ms） | — |
| ASR final | 600 ms | 超时 → 「我没听清，再说一次？」 |
| LLM 首 token | 900 ms | 超时 → 模板首句 + 继续等 |
| 结构化输出完成 | 1500 ms | 超时 → 用已有 evidence 走兜底打分 |
| TTS 首包 | 800 ms | 超时 → Polly / 预录音 |
| 整段播完 | 30 s | 截断 + 收尾句 |

**预热清单（开场前 10 分钟必须做完）**：Bedrock schema 首编译（最长 90 s）、TTS 连接与音色、prompt 缓存、ASR 连接、DNS/TLS 常连接。

### 4.3 判决逻辑放在上位机（不在 LLM 里）

```
LLM 输出：evidence[3]（每条引原话）+ scores{敢,要,想,守}
代码：house = argmax(scores)
      若同一 house 连续 3 次 → 本次 scores[house] *= 0.85 后重算
      校验：evidence.quote 必须能在 ASR final 文本里找到（编辑距离 ≤2），否则重试 1 次
      失败 → 兜底打分（4 个问题 × 权重）→ 仍能出结果
```

**为什么**：LLM 会漂移、会讨好；判决必须是确定性的、可复现的、可单测的。

### 4.4 观测：6 个时间戳

```
t0 设备 speech_end（设备时钟）
t1 网关收到最后一帧
t2 ASR final
t3 LLM 首 token
t4 TTS 首包
t5a 设备播放沉吟首帧（预录）
t5b 设备播放真实内容首帧
```
据此算 **TTFV = t5a − t0**（含沉吟）、**TTFC = t5b − t0**（真实内容首字，这是对外报的数）、各段耗时；每场写一行 JSONL，路演时直接投屏「1.4 s」。

> ⚠️ 不要用 `t4 − t5` 之类只覆盖最后两段的公式——那会得到一个漂亮的假数字（约 340 ms）。TTFC 的定义只有一条：**观众最后一个字 → 他听到第一个真实内容字**。

### 4.5 部署三形态

| 形态 | 组成 | 优点 | 缺点 | 用在哪 |
|---|---|---|---|---|
| **本地**（推荐演示） | 笔记本：网关+编排+adapter；云只做 ASR/LLM/TTS | 可控、可改、延迟低 | 笔记本要稳，别休眠 | 彩排与舞台 |
| **混合** | 笔记本跑网关，云跑全部模型 | 与本地相同，云端可观测 | 两处网络 | 路演备用 |
| **全云** | EC2/Fargate 常驻 | 不依赖笔记本 | 跨境延迟不可控 | 提交视频/赛后 |

**铁律**：舞台上**不要**让笔记本连场馆 Wi-Fi；用手机热点，且提前把热点名/密码写进设备。

## 5. 接口契约（三层之间的三张表）

### 5.1 硬件 ↔ 下位机

| 契约 | 内容 | 冻结时间 |
|---|---|---|
| 引脚表 | 2.2 节那张表 | 今晚 G1 前 |
| 采样格式 | 16 kHz / 16 bit / 单声道 / 32 ms 帧 | G1 |
| 播放格式 | 24 kHz（或 16 kHz）/ 16 bit / 双缓冲 | G2 |
| 电平 | 麦增益、喇叭音量档位（0–100，默认 70） | G2 |
| 灯语 | 6 种状态 ↔ 颜色/呼吸 | G2 |

### 5.2 下位机 ↔ 上位机（摘要，全文见 `00-protocol.md`）

| 方向 | 消息 | 频率 | 失败处理 |
|---|---|---|---|
| 设备→云 | `hello`（caps/版本） | 连接时 | 3 s 无 `ready` → 重连 |
| 云→设备 | `ready`（sid/参数） | 连接时 | — |
| 设备→云 | `listen{start/stop/detect}` | 会话 | 无响应 5 s → 回 IDLE |
| 设备→云 | 二进制 Opus 帧 | 60 ms | 不重传，跳号 >10 记错 |
| 设备→云 | `abort` | 打断时 | 忽略失败 |
| 云→设备 | `stt` / `llm` / `tts{start/sentence/stop}` | 流式 | 设备只依赖 `tts` 与音频 |
| 云→设备 | `result{house,reasons,latency}` | 会话末 | 缺失则只播 TTS |
| 设备→云 | `bye` | 结束 | — |

### 5.3 上位机 ↔ 云厂商

| 依赖 | 接口 | 关键参数 | 失败降级 |
|---|---|---|---|
| ASR | Transcribe Streaming（HTTP/2 双向流） | zh-CN、16 kHz、partial | 阿里 fun-asr |
| LLM | Bedrock Converse / InvokeModelWithResponseStream | 结构化输出 schema、温度 0.8 | Nova Lite |
| TTS | CosyVoice WebSocket | instruction 音色、24 kHz | Polly Zhiyu / 预录 |

## 6. 四类故障的责任分工

| 故障 | 谁发现 | 谁决策 | 谁兜底 | 观众看到 |
|---|---|---|---|---|
| Wi-Fi 断 | 下位机（心跳超时） | 下位机 | 下位机：切按钮模式 + esp-tts | 灯转黄，帽子说「我们换个方式」 |
| ASR 超时 | 上位机（计时器） | 上位机 | 上位机：发提示句 TTS | 「我没听清，再说一次？」 |
| LLM 超时 | 上位机 | 上位机 | 上位机：模板首句 + 兜底打分 | 帽子仍宣判，理由变通用 |
| TTS 超时 | 上位机 | 上位机 | 上位机：Polly / 预录音 | 音色变，但不卡 |
| 麦克风坏 | 下位机（无信号/自检） | 下位机 | 下位机：按钮模式 | 灯转黄，直接选 4 题 |
| 喇叭坏 | 下位机（播放无声，需自检或人工） | 人 | 换第二顶帽子 | 30 秒换帽 |
| 云端 5xx | 上位机 | 上位机 | 重试 2 次 → 降级 | 延迟变长但不死 |
| 证书过期 | 上位机/设备 | 人 | 备用证书 | — |

**原则**：**谁离故障近，谁做检测；谁掌握替代方案，谁做兜底。** 上位机不要试图救 Wi-Fi，下位机不要试图救 LLM。

## 10. 每层的验收清单

### 硬件
- [ ] 帽本体 ≤150 g，整机 ≤350 g
- [ ] 木棒平衡点落在帽箍中心 ±3 cm
- [ ] 1 m 处语音 Leq 68–72 dBA
- [ ] 帽体隔离度 ≥25 dB（麦孔封泥对比法）
- [ ] 连续 2 h 温升 <10 ℃
- [ ] 20 秒换人流程走通 10 次

### 下位机
- [ ] 冷启动到可听 ≤3 s
- [ ] 10 次会话不重启
- [ ] 心跳 15 s；**断网 1.2 s 内检测到**、**5 s 内按钮模式就绪**（两个数，别合成一个）
- [ ] 按钮打断 300 ms 内静音
- [ ] 灯语 6 态正确
- [ ] 低压保护触发后能播完当前句

### 上位机
- [ ] 三个 adapter 单独可跑（curl/脚本驱动）
- [ ] 判决纯函数单测通过（含反集中）
- [ ] 四类超时都能降级
- [ ] 6 个时间戳齐全，误差 <200 ms
- [ ] 预热脚本一条命令跑完
- [ ] 大屏 console 能显示字幕 + 延迟
