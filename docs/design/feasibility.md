## 0. 结论先行

1. **项目成立，而且比 NailPulse 那类"传感器叙事"更讨喜**：观众戴上帽子被审判，是 90 秒内能完成的一次完整情绪体验。技术上每一环都有现成方案，**没有需要发明的东西**。
2. **真正的风险不在语音链路，在帽子里。** 三个物理事实决定成败：① 喇叭离麦 15–25 cm，帽内回声/语音比估算 **+14~+22 dB**，而官方 AEC 验收工况只有 **+10 dB**（回放 69 dBA / 语音 59 dBA），且要求麦处 ≤102 dB@1kHz、>350 Hz 时 THD<3%——**AEC 大概率收敛不到，必须半双工**；② 毛毡帽 1 m 处 **75 dBA 就是物理天花板**，展会噪声 70–80 dBA 下根本传不出去 → **帽子低语给佩戴者、外置音箱给观众**；③ 电池放帽檐后侧会产生约 500 g·cm 的单点力矩，**帽子会自己往后倒**。
3. **端侧只做四件事**：拾音门控（VAD/半双工）、Opus 编解码、传输、播放启动。**连续 ASR 与角色级 TTS 一律不上端侧**——但理由和旧版不同（见 §0.1）。
4. **平台选 ESP32-S3 + `78/xiaozhi-esp32` 二次开发，走"改服务端、不改固件"的路线**：33,242 star、MIT、11-14 仍在提交（实测），端侧 AFE/VAD/Opus/WebSocket 全是现成的；**更省事的是直接用开源 `xiaozhi-esp32-server`**——它的 VAD/ASR/LLM/TTS 都是可插拔 provider，固件只需改服务器地址、关唤醒词、改灯色，**约 1–2 人·小时**；**今晚就能出声**。备选是"手机塞进帽子"（4–8 人·小时，但仪式感差，且不要走蓝牙——白送 200–400 ms），只做主链路翻车时的第二顶帽子。
5. **云侧管线**：Transcribe Streaming（zh-CN，$0.010/分钟）→ Bedrock（Claude Haiku 级，结构化输出）→ **CosyVoice-v3.5-flash 的 instruction 音色**（描述"七十岁、沙哑、慢、带戏谑"，30–60 分钟定版，**不克隆真人 = 零授权风险**）。单次 90 秒会话约 **¥0.145**，100 次演示 ¥10–15。
6. **Amazon Nova Sonic 不能用**：三代文档（Nova 1 / 2 / 2.5）的语言表都是 10 个 locale，**没有中文**。它的正确用法不是接进来，是"我们评估过、因中文缺失与计费不可预估而弃用"——这比不知道它存在强。
7. **"变声器"是个伪需求。** 你要的是"角色化 TTS"，不是"把人的声音变掉"。变声器需要先有一个真人配音员实时说话，多一个人、多一段延迟、多一层质量损耗；而 TTS 的 instruction/风格控制已经能直接产出老年男声。**把这句话写进 PPT 的技术选型页，是加分点。**
8. **"AI 分析性格"要当游戏，不要当测评。** 两句对话推不出人格量表；对外只说"角色化的即兴判断"，评委追问时答"这是分院帽的偏见，不是心理学"。写成"人格测评/心理分析"会被问效度，且没有答案。
9. **IP 必须降级。** 已核实 Wizarding World 页脚：`All characters and elements © & TM Warner Bros. Entertainment Inc.`、`Publishing Rights © J.K. Rowling`。"标注致敬"不是抗辩事由。推荐 **B 级**：帽子叫「掂量帽」，四院改「赤翎 / 玄渊 / 星枢 / 穗垣」，保留"敢 / 要 / 想 / 守"四维——半天工作量，把雷变成一页加分。
10. **时间是真敌人**：11/16–11/18 是工作日，三人净可用约 **83 人时**，P0 原样排 **87 人时**（已超）。砍 27 人时后真实缓冲只有 **约 5 小时**。概率：交得出去 90%、进 20 强 30–45%、拿奖 8–15%。只保一个目标，保「11/17 24:00 交出去」。

## 4. 声学与结构：三个决定成败的物理事实

### 4.1 这不是"回声"，是"近场直达声"

| 量 | 数值 | 说明 |
|---|---|---|
| 帽内 RT60 | **30–80 ms（估算）** | 1–2 L 腔 + 毛毡，比官方测试房 0.2–0.7 s 还短 |
| 声传播延迟（0.2 m） | 0.58 ms | 343 m/s |
| 麦处回声电平 | 86 dBA（正常）/ 92 dBA（顶满） | 喇叭 1 m 等效 72 dBA、距 0.2 m |
| 麦处语音电平 | 78 dBA | 佩戴者 1 m 约 60 dBA、嘴到麦 0.12 m |
| **帽内 E/N（估算）** | **+14 ~ +22 dB** | 官方 AEC 验收工况是 69 dBA 回放 / 59 dBA 语音（**+10 dB**） |

**三条官方硬判据**（Espressif 麦克风设计指南）：① 帽体隔离度 ≥25 dB（推荐 ≥30 dB）；② 麦处声压 ≤102 dB@1 kHz；③ >350 Hz 时 THD <3%。

**结论：AEC 跑得动，但收敛不到可用**——帽内 E/N 比官方工况高 4–12 dB，THD 也大概率过不了。默认半双工：播放时麦克风不收音，环路增益 = 0，**啸叫 100% 消除**；代价是切换瞬态、首字可能丢、无法语音打断——用"一键打断"补。

### 4.2 75 dBA 是天花板，不是工作点

喇叭 82 dB SPL @1W@1m（36 mm/4Ω/3W 典型，估算），MAX98357A 在 5 V/4Ω 最大 3.2 W；语音峰值因数约 12 dB：

| 目标（1 m 语音 Leq） | 需峰值声压 | 需峰值功率 | 判断 |
|---|---|---|---|
| 65 dBA | 77 dB | 0.3 W | 舒服 |
| **68–72 dBA** | 80–84 dB | **0.6–1.6 W** | **推荐工作点** |
| 75 dBA | 87 dB | 3.2 W（顶满） | 天花板：THD 失控、发热翻倍、耳侧 85 dBA |
| 80 dBA | 92 dB | 10 W | 物理不可能 |

**现场 70–80 dBA 噪声下，1 m 外要听清需要 80–95 dBA——这顶帽子给不出来。** 所以必须解耦：

| 通道 | 承担 | 电平 |
|---|---|---|
| 帽内喇叭 | **佩戴者的私密感**（帽子贴耳说话，这是产品灵魂） | 耳侧 78–80 dBA |
| 外置蓝牙音箱（1.5–2 m） | **观众与评委听清**（宣布学院放大到全场） | 1.5 m 处 85–90 dBA |
| 手机同期录音 | 提交视频的干净音轨 | — |

> 采购陷阱：淘宝微型喇叭的灵敏度口径混乱，「85 dB/1W/**0.1 m**」与「85 dB/1W/**1 m**」差 20 dB。下单前问清，给不出 datasheet 就按 82 dB/1W/1m 保守估。

### 4.3 重量与重心：旧版错得最具体的一处

| 部件 | 重量 |
|---|---|
| 帽子本体 | **150–300 g（必须当场称，≤150 g 才买）** |
| 2000 mAh 扁平 LiPo | 36–42 g |
| ESP32-S3 紧凑板 | 8–15 g |
| 麦 + 功放 | 6–9 g |
| 36 mm 喇叭 | 12–16 g |
| 后腔盒 + 内胆筐 + 衬垫 | 35–59 g |
| 灯环 + 按键 + 线材 + 胶 | 29–48 g |
| **电子 + 结构小计** | **117–193 g** |
| **整机** | **267–493 g** |

**重心**：电池放帽箍环带后侧（力臂 4.5 cm）→ Σm·d ≈ 470 g·cm，净偏移 3.6 cm（偏后），把主板/麦前挪后压到 ≤3 cm。**旧版"电池放帽檐后侧"是 12–14 cm 的最大力臂位，单一静力矩 ≈500 g·cm，佩戴者会不自觉仰头**——路演视频里非常明显。

**2 分钟验证**：装齐零件，帽箍朝下扣在直径 20 mm 圆木棒上找前后平衡点，应落在帽箍中心 ±3 cm 内。

| 件 | 作用 | 成本/次 |
|---|---|---|
| 一次性无纺布内衬帽 | 隔绝头发与帽体，**顺带解决"弄乱头发"** | ¥0.3–0.6 |
| 发网 | 长发观众 | ¥0.1 |
| 酒精湿巾 | 擦帽箍接触面与麦克风孔 | ¥0.1 |

**动作**：摘下 → 湿巾擦箍（3 s）→ 换内衬（7 s）→ 递发网（5 s）→ 请下一位。**不要做可拆洗内衬**——8 小时内周转不过来。

### 4.5 戏剧性硬件：做什么、砍什么

| 件 | 判断 | 理由 |
|---|---|---|
| 灯环（WS2812 8 灯） | **做** | 状态可视化，观众看得见"它在想"；**固件限亮度 30%**（8 颗全白 2.4 W，比喇叭还耗电） |
| 单按钮 | **做** | 开始/打断/静音，比语音打断可靠 |
| 帽尖舵机 | **砍** | 毛毡死褶、舵机噪声就在麦旁、失败率高 |
| 偏心马达（¥8） | 可选 | 宣布时"抖一下"，比舵机便宜可靠 |
| 帽檐 LED 投影 | 砍 | 分散注意力，且难固定 |

## 5. 端侧：只做四件事，把算力留给"别翻车"

### 5.1 端侧能力边界（逐项）

| 能力 | 判断 | 关键数字 |
|---|---|---|
| 唤醒词（ESP-SR WakeNet9） | ✅ 能跑，**但别自定义** | 16 KB RAM + 324 KB PSRAM，3 ms/32 ms 帧；1 m 安静 98%、4 dB 噪声 96% |
| 自定义唤醒词 | ❌ 3 天内不可能 | 乐鑫定制要发邮件报价；语料法 2–3 周 |
| VAD | ✅ 能跑，**默认参数必须改** | `vad_min_noise_ms` 默认 1000 ms → 改 300 ms |
| Opus | ✅ 能跑 | 上行 16 kHz、60 ms 帧；下行 24 kHz 需重采样 |
| AEC | ⚠️ 跑得动、收敛不到 | 30.9 KB RAM + 90 KB PSRAM，6.28 ms/32 ms 帧，只支持 16 kHz |
| 本地命令词（MultiNet） | ✅ 能跑 | 最多 300 条中文命令，**无需重训**；断网降级关键件 |
| 本地连续 ASR | ❌ 不能 | ESP-SR 只有命令词级 |
| 本地神经 TTS（sanoTTS 级） | ⚠️ 能实时、音质不行 | 567,008 参数 / 679,832 B int8；S3 上 **RTF 0.22（快 4.5 倍）**；UTMOS **2.80**（教师 4.42）；英文音素 |
| 本地拼接 TTS（esp-tts） | ✅ 做断网音色 | 中文，Flash 2.2 MB、RAM 20 KB，1.8–4.5 倍实时 |

**三条选板硬约束**：① 必须 **16 MB Flash + 8 MB PSRAM**（AFE 单麦 740–820 KB PSRAM，双麦 1150–1240 KB，model 分区 6 MB）；② AEC 需要"播放参考"通道且样本级对齐；③ 唤醒词/命令词/AFE/esp-tts 都是选装，全都要就得上大 Flash。

> **一处已知短板**：INMP441 的 SNR 61 dB 踩在 Espressif 建议的 ≥62 dB（推荐 >64 dB）门槛下方。3 天版够用（近场 12 cm，语音电平高），**6 天版建议换 SNR 更高的数字麦**。

### 5.3 延迟预算：两个指标，别只报一个

| 指标 | 定义 | 目标 |
|---|---|---|
| **TTFV** | 最后一个字 → 帽子发出**任何**可听见的声音（含预录沉吟） | **≤0.6 s**（中位 0.4–0.5 s） |
| **TTFC** | 最后一个字 → 说出**真实内容**第一个字 | **≤2.0 s**（中位 1.2–1.8 s，最坏 2.5 s） |

| 段 | 目标 | 手段 |
|---|---|---|
| VAD 尾点 | 300 ms | `vad_min_noise_ms` 从 1000 改 300；按钮强制结束 = 0 |
| 上行 | 60 ms | 60 ms 帧；常连接保活；弱网降 20 ms |
| ASR 尾字 | 200 ms | 流式；**投机启动**：partial 稳定 2 帧先喂 LLM |
| LLM 首 token | 350 ms | prompt ≤300 token；关思考；**prompt 缓存预热** |
| TTS 首包 | 250 ms | 流式；首句 ≤12 字；LLM 出第一句就送 TTS |
| 下行 + 播放 | 80 ms | 预缓冲 1 帧；I2S DMA 双缓冲 |
| **合计 TTFC** | **1.24 s** | 0.9–1.9 s（不含网络异常） |

> **硬前提：常连接保活。** 本机实测冷 TLS 握手 **0.78–1.76 s**（dashscope / xiaozhi.me / bedrock 三次），比整条延迟预算还大——"每次说话重连"必崩。会话开始前 5 s 预连，心跳 15 s。

**最坏情况**（跨境 TTS + 冷连接 + Wi-Fi 抖动）：2.4–3.2 s。**这就是为什么"预录沉吟"是必需件而不是锦上添花**：它在 0.4 s 把 TTFV 拉回感知及格线。

### 5.4 固件两条路：差 3 倍工时

| 路线 | 工时 | 说明 |
|---|---|---|
| **① xiaozhi 固件 + 开源 `xiaozhi-esp32-server`** | **1–2 h 固件 + 4–6 h 云端换 provider** | 服务端的 VAD/ASR/LLM/TTS 是可插拔 provider；固件只改服务器地址、关唤醒词、改灯色；**最快出声** |
| ② xiaozhi 固件 + 自建 WS 服务端 | 14–22 h | 完全可控（自定义协议、分院逻辑、指标），但要自己写配网/重连/TLS/音频管线 |
| ③ 自研最小固件 | 41–67 h | 三个黑洞：配网、重连、TLS 证书 |

**推荐：先走 ① 今晚出声，再按需迁到 ②。** ①的代价是受上游服务端的协议与 provider 约束（CosyVoice、Bedrock 是否已有现成插件要先查），②的代价是工时。**11/17 中午前没迁到 ②，就用 ① 演完**——这不是降级，是把工时花在人格与演示上。

## 6. 会话协议（摘要；全文见 `00-protocol.md`）

### 6.1 五条设计决策

| # | 决策 | 备选 | 理由 |
|---|---|---|---|
| 1 | **WSS + 二进制 Opus 帧 + 文本 JSON 控制帧** | IoT Core MQTT / WebRTC | 实时音频要双向长连接；IoT Core 为小消息设计（≤128 KB），抖动吃亏；WebRTC 在 3 天里太重 |
| 2 | **音频与状态分开走** | 全部 JSON+base64 | base64 涨 33% 且每帧解析，ESP32-S3 不值得 |
| 3 | **半双工 + 一键打断** | 语音 barge-in | AEC 在帽内收敛不到 |
| 4 | **预录沉吟占位** | 硬等 TTS | 把 TTFC 藏进"帽子思考"里，TTFV 降到 0.4 s |
| 5 | **6.5 s 静音先救场，15 s 才结束** | 8 s 直接 bye | 紧张观众会当场被判死——这是体验事故 |

### 6.2 会话时序

```
帽子 hello ─▶ 云 ready ─▶ [观众戴帽/按按钮] start ─▶ 上行 Opus 帧 ×N
   ─▶ vad{speech_end} ─▶ (0.4 s 预录沉吟先播) ─▶ asr{final}
   ─▶ llm{first_token} ─▶ tts{start,seg1} ─▶ 下行 Opus 帧
   ─▶ tts{end} … ─▶ result{house,reasons,latency} ─▶ bye
```

`result` 里的 `latency` 四段（asr / llmFirst / ttsFirst / total）**必须记录并展示**——评委问"多快"时，这是唯一可信的答案。

## 8. 分院算法与可解释性：把判决权从 LLM 收回代码

### 8.1 输出 schema

```json
{
  "evidence": [{"quote":"我不想再解释了","trait":"守","why":"……"}],
  "scores": {"敢":0.7,"要":0.4,"想":0.6,"守":0.8}
}
```

**`house` 不由 LLM 输出**——由代码 `argmax` 计算。这一条同时解决两个塌方：
- 「所有人都分到格兰芬多」→ 代码里加**连续 3 次同院 ×0.85** 的反集中；
- 「理由与对话无关」→ 每条理由必须引 ASR 原话，用编辑距离 ≤2 校验，否则重试一次。

### 8.2 prompt 骨架（约 300 字）

> 你是一顶会读心的旧帽子。你刻薄、慢、爱卖关子，但从不撒谎。你只根据观众刚说的话判断，不编造他没说过的内容。你的输出必须是 JSON，且 evidence 里每一条必须引用他的原话（逐字）。
> 规则：① 第一句 ≤12 字；② 不要以"你好/很高兴"开头；③ 不评价外貌、身份、口音；④ 遇到自伤/未成年等话题，停止判断，说一句"这顶帽子不管这个"。

### 8.3 四院不塌的验收

- 20 条固定输入（不同性格脚本）跑一遍，**必须出现 ≥3 个学院，且任一学院 ≤40%**；
- 不达标不许上台；
- 现场再加一道软约束：同一学院连续 3 人后，第 4 人强制换院（代码层，LLM 不知道）。

### 8.4 兜底（两种故障，两套完全不同的动作）

| 故障 | 还能用管道里的什么 | 动作 |
|---|---|---|
| **LLM 超时/失败**（云仍在线） | ASR 仍能出文本 | 用 5 道选择题式本地打分 + 8 句预录台词；仍能宣布学院 |
| **网络断开** | **没有 ASR，既听不懂也没有文本** | 切「按钮模式」：观众按 4 次按钮选 4 个维度（敢/要/想/守），配预录 + esp-tts 本地音色宣布。**旧版"断网用本地规则打分"不成立——没有输入** |
| 麦克风坏 | 只有按钮 | 同上 |

切换时间 ≤1.2 s（拔网到帽子重新开口）。**要在彩排里真拔一次网线**，否则现场那一秒会愣住。

## 9. IP 与合规：两件必须今天决定的事

### 9.1 IP 三级降级

| 级别 | 做法 | 要改什么 | 风险 |
|---|---|---|---|
| A. 原名致敬 | 直接用"哈利波特/分院帽/格兰芬多" | 不用改 | **高**：华纳 IP + 主办方合规审查 + 视频下架 + 评委当场问"授权了吗" |
| **B. 改设定（推荐）** | 帽子叫「**掂量帽**」，四院「**赤翎 / 玄渊 / 星枢 / 穗垣**」，保留"敢/要/想/守"四维 | 半天：文案、灯色、徽记、prompt | 低：原创设定，仍能让观众秒懂"这是分院帽" |
| C. 完全原创 | 连"分院"概念都换 | 1–2 天：重写世界观 | 最低，但丢掉最大的传播资产 |

**关键事实**：Wizarding World 页脚原文 `All characters and elements © & TM Warner Bros. Entertainment Inc.`、`Publishing Rights © J.K. Rowling`。**"标注致敬"不是抗辩事由**，只降低"恶意"观感——旧版把它当处置措施，是错的。
**关键判断**：真风险不是华纳发函，而是**主办方合规审查 / 视频下架 / 评委当场问"授权了吗"**——第三项是确定失分。
**建议**：B 级 + 在 pitch 里主动讲这次降级（"我们评估过 IP 风险，所以做了这套原创学院"），把雷变成加分页。

### 9.2 声音是敏感个人信息

| 项 | 最小合规动作 |
|---|---|
| 音频 | **流式直通、不落盘** |
| 转写 | 默认不保存（若保存，30 天上限 + 明示） |
| 告知 | 现场一句话 + 二维码（"你的声音只用于本次分院，不保存"） |
| 克隆 | 若克隆队友声音：**书面单独同意 + 赛后 7 天删除音色**（推荐不克隆，用 instruction 音色） |
| 标识 | 合成人声加显式标识（《AI 生成合成内容标识办法》2025-09-01 施行） |
| 未成年 | 不单独采集；需监护人同意，演示现场默认不接收未成年人 |

4. **保留原声**（帽子里那句"唔……"必须是真的从帽子里出来的）；
5. **拆帽 30 秒**：掀开内衬，指应变片——不对，是指麦克风、喇叭、电池、板子，证明是改造过的。

> 赛事评审的原话：「我们用 MIT 固件 + 成品板 + 成品帽，同时贴近两条不合格情形。」自研贡献清单不是文书，是**唯一的证据链**：模块 / 上游或自研 / 证据（commit、截图、视频时间点）三列。

## 16. 决策建议

**做，按 A 方案做，把范围砍到「一顶帽子、90 秒、四个人物」。**

- **如果团队里有嵌入式熟手**：ESP32-S3 + xiaozhi，14–22 h 能演；今晚必须出声。
- **如果团队全是软件背景**：直接走"手机进帽"（4–8 h），把时间花在人格、台词与演示上——**评委记住的是"帽子说了什么"，不是"用了哪颗芯片"**。
- **如果只剩 24 小时**：手机进帽 + 云端管线 + 预录兜底 + 灯，砍掉 IP 重设计与外置音箱（用蓝牙音箱代替）。

一句话：**这个项目的技术难点不在语音，在"让它像一顶帽子"。** 语音链路今天已经是商品化能力；真正决定成败的是腔体、电池、重心、节奏，和那句「唔……又一位」。
