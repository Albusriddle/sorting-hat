## 2. 卡在哪：三件事按优先级

### P0 · 固件 `THINKING` 没有超时（会"卡死"）
Wi-Fi 抖动时 `comm_send_*` 全部静默丢弃，但设备本地照样 `go(THINKING)`；`THINKING` 无任何超时，按钮又是空桩（`HAT_ENABLE_BTN` 关闭）→ **只能串口 `b` 或断电**。
→ 交给 A：`THINKING` 15 s 超时回 `ARMED`。这是唯一"一次抖动 = 一台必须断电的帽子"的风险。

### P1 · 板上固件落后仓库四处
`t0` 打点位置、识别后补发 `vad{speech_start}`、`LISTEN_TIMEOUT_MS=30000`、时间戳有符号打印。
→ 交给 A：烧 `main`，回传开机横幅 + `[WS-TX] vad speech_start` + `[TS] TTFC=`（正数）。

### P2 · 没有"可以说了"的反馈
唤醒后既无提示音也无灯；观众只能干等，直接吃掉 12 s 预算。`PH_ASK`（"说吧，孩子。"）已在 `phrases_gbk.h`，只被串口 `a` 用到。
→ 交给 A：唤醒即播 `PH_ASK`。零硬件、零新模块。

## 4. 演示脚本（主持用）

1. 观众站到帽子前 **10–20 cm**，安静侧；
2. **喊"开始"** → 等提示音（当前版本：等 0.5–1 s）；
3. **慢说**一句短词条（如"我怕输"）；
4. 帽子念桥接句 → 判院 → 念学院名；
5. 帽子说话时**不要说话**（半双工是假的，识别芯片仍在听）；
6. 没成 → **重新喊"开始"**再说一次，最多 2 轮；第 3 次请下一位。

**别做的事**：不要说长句、不要连说两句、不要在帽子说话时插话、不要等超过 10 s 才开始说。

## 8. 接手须知（代码侧）

- 入口：`host/app/run.py` 同时起 device(:8443) 与 admin(:8080)；`host/tasks.py` 是任务入口。
- 改参数：优先 `/v1/config`（有校验+回滚），或改 `host/app/config.py` 默认值。
- 改协议：先改 `host/app/protocol.py` + `docs/00-protocol.md`，再改固件。
- 加测试：`host/tests/`，跑 `python -m pytest -q`（应 60 passed）。
- 记录键是 `sid#轮次`：同一条连接跑多场不会互相覆盖；不要退回按 `sid` 存。
- 硬上限必须 < 固件 `LISTEN_TIMEOUT_MS`：现在 28 s < 30 s，改任一边都要一起改。
- 文档改数值时全域 grep：`passed`、`9999`、`12000`、`28000`，避免只改一处（已踩过）。
